# Contributing

Thank you for helping. This project is at the design stage: ideas, questions and fixes are welcome, but a change that does not fit the author's own network may be declined.

---

## Development workflow

| Step | Command / Action | Description |
| :--- | :--- | :--- |
| **1. Issue** | Open or pick an issue | Optional for a small fix. |
| **2. Branch** | `git checkout -b type/short-name develop` | Create a branch from `develop`. |
| **3. Change** | *(your editor)* | Keep the change small. |
| **4. Commit** | `git commit -m "type(scope): subject"` | In English, 72 characters at most. |
| **5. Push** | `git push origin type/short-name` | Push and open a pull request to `develop`. |

A pull request is merged with a merge commit. Direct pushes to `main` and `develop` are blocked.

---

## Rules

- No real device list, MAC address, IP plan or router setting in the repository, not even in a test or an example. Use made-up values.
- Comments are on their own line, above the code.
- No long dashes: use `-`.

---

## Language

Code, comments, commits, issues and pull requests are in English.
